# Generic starter rewrite

Issue: #1. The user approved the preceding comparison and requested its implementation.

## Accepted outcome

AGENTS.md and the skills become portable decision guidance. Preserve user authority,
project choices, existing work, evidence honesty and applicable delivery gates. Remove
code examples, copied identities, mandatory technology/architecture choices and absent
execution-skill dependencies. Keep repository maintenance policy outside the portable
package. The generic root is the canonical shared policy; skills supply task procedures.

Retain the ten skill names for discovery continuity, narrow overlapping triggers and
make GitHub adapters optional. Add systematic debugging and additive project initialization
as self-contained procedures. Remove the obsolete visual-server bundle and copied
authoring/release references after checking their callers. No application, dependency,
test framework or CI pipeline is introduced. Simplify inherited ignore rules to local
secrets and workstation artifacts without hiding target-project source.

## Delivery steps

1. Document adoption, project configuration, maintenance policy and validation scenarios;
   commit the agreed intent before modifying the package.
2. Establish the old package's decision failures with isolated reader scenarios and
   direct source checks. Preserve evidence honestly; no manufactured red/green history.
3. Rewrite root guidance and skills; remove obsolete resources and add the changelog.
4. Validate metadata, references, absence of code/examples and project-specific policy;
   run representative decision scenarios, inspect the diff and address reader findings.
5. Commit, push and open a staging PR linked to the issue with actual results. Disclose
   missing hosted CI and leave integration pending unless all maintenance gates pass.

## Review focus

Check projects without software builds or forges, already authorized work, conflicting
local guidance, missing checks, experiments with existing edits, setup in an existing
repository, and moving release candidates. Acceptance is the issue checklist and the
observable decisions in the validation document, not a particular paragraph shape.
