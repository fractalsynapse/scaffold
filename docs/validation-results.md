# Generic starter validation — 2026-11-06

Issue: #1. This record covers the instruction-package rewrite on its issue branch.
It describes observed checks, not a guarantee of agent compliance in every environment.

## Baseline

A separate read-only reader applied the old guidance to six requests: an approved
documentation correction without a forge/build, a native library plan, API research
while writing docs, one-PR CI inspection, an environment-dependent website repair with
unrelated edits, and adoption into a differently configured project.

The reader identified concrete conflicting requirements: creation of a tracker/build
gate for prose, an unrelated documentation command, unavailable execution skills,
opposing research permissions, broad housekeeping gates for a narrow inspection,
and insufficient ownership safeguards around dirty work. These were instruction
walkthroughs and source observations; no downstream work was executed.

## Revised package

- All 12 skills passed the available skill-creator format validator. Their frontmatter
  was also parsed with the available YAML parser and checked against directory identity.
- All local Markdown link targets resolved. Portable files had no fenced/indented
  code blocks, command recipes, implementation examples or copied project/stack identities
  in the targeted scans and reader inspection. All 14 obsolete support files were removed.
- Temporary package-layout smoke checks exercised both the default skill directory and
  an alternate directory. Each contained the 12 copied starter skills plus a preserved
  existing local skill. Both root-to-skill and skill-to-root links resolved after adaptation;
  each layout had 27 links. Existing target policy and license bytes were preserved.
- A separate reader walked through the original six requests plus installed CLI behavior
  with a missing environment and a release with an advancing candidate/missing acceptance.
  The reader distinguished appropriate scoped actions from outstanding evidence and
  authority. This was an independent review, not a blinded evaluation: the reader also
  inspected the validation document. It performed no external writes or downstream tests.
- That review found two wording gaps: adoption instructions did not explicitly cover
  root-to-skill links, and planning could be read as forbidding real project file paths.
  Both were corrected; the reader re-read the changed text and confirmed resolution.
- Diff whitespace and the final changed-file inventory were checked before delivery.

## Limits

There is no application runtime, build or application test suite in this package.
Temporary layout checks validate the assembled Markdown package, not actual discovery
in every supported agent host or execution of a downstream application. No packages
were installed and no real target project was modified during evaluation.

The repository reports no hosted workflows, branch protection or rulesets. Hosted CI
therefore remains unavailable, not green; the staging PR stays open under this
repository's maintenance policy. No merge, release or production publication is claimed.

The source repository has no LICENSE file. This rewrite does not select a distribution
license or change target licenses; source licensing remains an explicit maintainer
decision outside this instruction rewrite.
