# Project configuration guide

Record verified facts in the project's existing canonical documents or configuration.
This guide is an optional checklist, not a required file format or a set of defaults.
Link existing decisions rather than creating a second source for the same policy.

| Topic | Establish when relevant |
| --- | --- |
| Purpose and scope | Intended audience, deliverables, exclusions and observable acceptance. |
| Authority | Decision owners, existing authorization and actions reserved for review. |
| Instructions | Applicable root/nested guidance, skill discovery locations and conflict resolution. |
| Ownership | Repository identity, component boundaries and writable scope. |
| Existing choices | Languages, architecture, tools and constraints already selected by the project. |
| Verification | Actual checks, their scope, environment prerequisites and where results are recorded. |
| Isolation | Test data, temporary resources, external services and separation from live work. |
| Documentation | Canonical references, intended vs delivered behavior and freshness checks. |
| Change tracking | Whether a tracker is used and which work requires an issue or equivalent record. |
| Version control | Whether used, source/base branches, work-branch conventions and remote transport. |
| Review and integration | Required checks/review, who may merge and which branches are protected. |
| Release | Whether releases exist, candidate identity, versioning, changelog and publication authority. |
| Closure and cleanup | When work is considered delivered, how issues close and which resources may be removed. |
| Adoption | Approved skill source/version, destination, local adaptations and retained license notices. |

Distinguish verified, undecided and not applicable. A missing setting does not grant
permission to publish, delete or choose an architecture. Discover what is available;
ask only when a missing decision affects the authorized work. Do not install tools,
introduce a forge or create a release pipeline just to fill this checklist.
