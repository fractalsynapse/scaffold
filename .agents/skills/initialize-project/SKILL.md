# Adopt guidance without replacing project choices

Follow the source and target's applicable instructions and the user's selected scope.
Loading this skill does not authorize setup. Confirm the intended project, destination,
existing guidance, skill discovery mechanism and applicable licenses. Verify canonical
repository identity when version control is present; a directory name alone is insufficient.

Inspect existing files, dirty state and ownership before any change. Select the approved
source/version and exact setup inventory. Preview collisions and reconcile instructions
with existing decisions; do not silently overwrite guidance or delete the current tree.
Use an isolated location for inspection when necessary. Preserve source provenance,
license notices, executable modes and required resources. Do not follow unexpected
symlinks or copy private state, credentials or runtime artifacts into the target.

Copy only authorized guidance and selected skills into the supported destination.
Reconcile conflicting policies through applicable precedence and ask only about material
unresolved decisions. A generic starter must not replace the target's architecture,
language, branch model, release process or license. Record verified project facts in
its existing canonical location, leaving undecided or inapplicable values explicit.

Check installed metadata, resource references and skill discovery in the actual agent
environment. Adapt both root-to-skill links and skill-to-root links for the chosen
directory name and depth; include referenced skills or reconcile their procedures.
Walk through a representative target task to confirm that
local decisions remain effective. Report source identity, destination, adaptations,
verification and any retained conflicts. If discovery cannot be exercised, disclose that.

Finish at the requested setup boundary. Adoption does not authorize application code,
dependency installation, a new forge or branch policy, publication, changing protections
or initializing other projects. Continue implementation only when it is already within
the user's authorization and any explicitly pending setup review is resolved.
